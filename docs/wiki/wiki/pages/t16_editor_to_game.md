# How the editor maps to the game

Pack `t16_editor_to_game`. For every user-visible control of the MechAssault 2 Scenario Editor: what it writes to the map file, how the game uses that data, and the wiki facts that explain it.

Confidence: 'code-confirmed' means the write was read in editor code; the game-side meaning carries the linked fact's own confidence.

## Map, Terrain, Paint, Water, Plants, Environment, View

Wiki: non-superseded facts only. All paths below are relative to `editor\src`.

Reading the tables: "Code ref" is where the write was read. Confidence = `code` (I read the write in editor code) + the game-side fact's own confidence in brackets. "gap" = no wiki fact explains the game effect. File names use the saved-archive convention `Terrain/Scn<id>_*.tif` (core/scenario.cpp:1863-1895). Everything lands in `world.wdf` (the MAEnvironment / MATerrain / MASky2 / MATerrainInfo / MARoot objects) or in a file of the .ma2map archive.

Abbreviations: ENV = MAEnvironment (found with `find_class(K_ENV)`), TER = MATerrain, TI = MATerrainInfo, SKY = MASky2.

### Surprises (editor vs wiki disagreements or wiki-internal conflicts)

1. Sun direction consumer: menv-fog-setter-args says "DirectionalLightDirection is never read by name (sun direction has no consumer, open)", while m15-model-v0-sun-has-extra-factor (verified-in-game) shows models light with c13 = DirectionalLightDirection, and menv-sun-colour-direction infers the offset. The editor's Sun sliders and lightmap bake assume the field is used.
2. Lightmap contents: the editor bakes sun diffuse into L (0.35 + 0.65 x N.L) and shadow into A. terrain-lightmap-channels says the game treats L as a baked ambient/sky term (x LightAmbientColor) and A as a shadow mask gating the vertex-lit sun term, whereas mgiC-terrain-pictures says "L is diffuse light". The editor's bake is not game-verified on an editor-made map.
3. Ground-layer neutral colour: "Show it in its own colours" uses 1/(4 x DetailBlend); terrain-detail-colour-gain-. (verified-in-game, UC/KF/NRC) says the gain is 8 x DetailBlend, RESOLVED: not a mismatch; the game's 8x includes the light doubling, the editor's albedo is 4 x DetailBlend with x2 light, so 1/(4 x DetailBlend) is right in both (render.cpp tps; matched in game on a new map 10-25).
4. Type map value 8: terrain-type-map says 8 = special (water/waterway), the editor uses 8 as "Water/special"; bs-mawater-size says 8 = shallow, 16 = deep, 32 = waterway. The editor only knows 0/1/2/8.
5. Description default text: editor-null-description-bug says "A custom scenario (by <author>)."; the code writes "A custom scenario by <author>." (core/scenario.cpp:1997) and strips that form when loading.
6. IsNightTime wiki conflict: isnighttime-values-unknown-and-only-reader-building-light-127ed7 / editor-evening-look-ui-grouping (values unknown, Bogged Down maybe 1) versus isnighttime-retail-values-all-worlds-34-on-26-off (full list). The editor's Look constants match the full list (Go Commando, Ill Wind, Bogged Down lit; Cold dusk, New River City, Witch Cauldron not).
7. The Night checkbox label implies darkness, but the game's IsNightTime does not darken (menv-lightning-night, isnighttime-buildings-only). When no Look matches, the box simply mirrors `IsNightTime`, so a bright map with lit windows shows Night ticked.
8. gap-environment-lighting and gap-culture-scatter (still "inferred", status not superseded) say the editor ignores lighting / does not draw culture scatter; both are now implemented (View > Game lighting, View > Ground scatter) and the "Night/Sun controls change saved data only" statement is stale.
9. gap-weather-lights says rain is not previewed; the editor now previews rain/snow/dust (screen-space) and snow via the game's particle effect.
10. Fog: fog-applier-modes-and-shadow-pass-mode-3 says FogMode 2/3 are identical fixed 0.1 VS-driven fog; the editor treats mode 3 as plain distance fog (app/app.cpp:2027) and only draws the height band for mode 2. Not exposed in these panels, but the Height fog band help text is true only for mode 2 (matches fog-mode-2-vertex-program-height-band-formula-verified).
11. Editor writes `EnableLightning` although menv-lightning-night / menv-weather-layout say it is never read (harmless).

### 0. How the tab really works (read first)

- The current Triggers tab edits the level's own native objects in place (MATrigger*, MAAction* children, MAEvent orders, MoeEntitySet, MASwapSet). It writes **retail classes only**, copied from a retail prototype per class (`load_trigger_prototypes`, CT:103; `add_trigger_object` CT:919; `add_action_object` CT:953). There is no hidden compiled group for anything created in this tab (AT:1-3 header comment).
- The older model (`condition_kinds` / `effect_kinds`, CT:22-67: "When the mission starts", "Bring in reinforcements", etc.) survives only as a **legacy loader**: a file that still has `Scenario:triggers` is compiled once into ordinary objects by `convert_legacy_triggers` (CT:1179; called at SC:2170 on load, and `compile_triggers` at SC:1950 on save). Compiled legacy objects live in group "Editor Triggers" with names prefixed `[ed] `; the conversion strips the prefix and renames the group to "Triggers" (CT:1163-1177). Section 7 documents these legacy kinds because wiki facts `editor-workflow` and `editor-trigger-actions-map` still describe them as the live path.

- Read-only retail levels: all widgets disabled (`Dis d(ro)`), text at AT:451.

### Gaps

2. Box "outside" (VolumeStateTest 2): inferred only.

4. Timer: which of TrgTimerDurationSeconds / TrgTimerDuration the game reads is not recorded (editor writes both).
5. MAActionMissionVariableSet "clear" (VariableState 0): retail always 1; clearing is untested. The "Variable number (advanced)" box does not clamp to 0.29, the range the game accepts.

7. MAActionSound IsQueued / DelayBeforePlay and MAActionMusic MusicEvent (play/stop/swap/intensity) have code facts but no UI control.

### Gaps (controls whose game effect no wiki fact explains)

1. `MAFreeCameraController.bSkipTo` (Shots tree): no fact; `cinema-stop-and-advance` lists its effect as open.
2. `MACameraProperty.Offset` (eye and focus steps), `Endy` / `EndWidth` / `EndHeight` (screen-size step), `startRGB` / `startAlpha` / `endRGB` / `endAlpha` (colour filter): only step template names are known. Only `flags` is documented (`camera-path-duration-flags`).
3. `MAPath.useSpline`, `smoothIn`, `smoothOut`, `duration`: structure is documented (`cinema-path-pattern.`), but the game's interpolation for MAPath eye paths is not (the Catmull-Rom fact covers MACameraPan).
4. How the game aims the camera at `focusUID` (versus the path tangent): the cinema-camera fact lists the look rule as open.
5. Deleting a cutscene that a trigger still uses: no fact on what the game does with a `cinemaID` that does not resolve.
6. Briefing "Title" and "Briefing" text: no fact shows custom ids render on the briefing screen (`briefing-screen-open` only says the screen is skipped).
7. "Speaker or title (optional)" and "No caption" on "Show a message": the editor offers them, the game never shows the caption (`broadcast-caption-missing`, open game bug).
8. Objectives: nothing explains what happens if the copied MARoot has fewer than 30 `ObjectiveItemDesc<i>` keys (the editor sets only keys that exist, triggers.cpp:556-566; `NumObjectiveItems` is constant 30 in the game, `maroot-objectives-keys`).
9. "Add part": no fact lists which classes are safe under which parents.
10. "Duplicate" of units, AI orders (`MAEvent`) and triggers: game effect beyond entity-set membership not documented.
11. Save As / Test with an untitled scenario: fact `editor-test-f5-saves-untitled-scenario.` (code-read-not-run) conflicts with master code (see Surprises).
12. "Add part" and "Duplicate" of classes whose models are not in the base archive: `palette-sweep-in-game.` shows an 80-object batch failing on heap, but no fact gives a per-object rule.
13. `--quick-test` on the game side: no single fact lists everything it does (only the Return key workaround and idle-player level restart are documented).
14. Cutscene "Preview" fidelity versus the game's shot player (letterbox bar size 11 percent, linear interpolation): no fact compares.

### Surprises

1. Preview fallback shot length is 5 s when `CameraDuration` and path duration are 0, but the game's `CameraDuration` default is 8 s (`camera-fov-and-shot-length`).
2. The "Game started" popup tells Mission testers the campaign intro movie plays first, but `custom-scenarios-no-spintro` says Custom Scenarios mode suppresses SPIntro (verified in test42). The editor text may be stale (the older `briefing-screen-open` fact said the intro played).
3. The Briefing title and text the Messages tab writes are never shown for a single custom mission: the game skips the briefing screen (verified-in-game), although `[Mission]`, `[Strings]` and MARoot ids are all written.
4. `editor-test-f5-saves-untitled-scenario-to-scenario-folder-as-name-ma2map` says Test saves silently to `<Name>.ma2map`; in master `cmd_save` with no file opens the Save dialog (app.cpp:1447-1453). Not merged, or changed since.
5. There is no Export. Save is the export; the game finds the file by scanning the scenario folder (Scenarios.ini). Test is a plain `--scenario` launch plus a menu walk inside the game.
6. "New cutscene" is built only from the retail Mission_05 data (`retail_world("Mission_05")`); without the disc data it fails with "the retail Mission_05 is needed as the model".
7. "Add shot" copies only the LAST controller (about 19 objects), moves it 25 m +X, and the Description gets " 2" appended each time; there is no reorder. "Delete shot" keeps pieces another shot still uses.
8. Objective text goes to three places on save: `[Strings] 60100+i`, `ObjectiveItemDesc<i>`, and ASCII text cut to 60 chars in `ObjectiveEditorName<i>` and `mfname<i>`.
10. Test refuses while any `MechAssault 2.exe` is running, because the game reads new or changed scenarios only at start or hub/menu rescan.
11. Cutscene Preview hides helper markers on purpose ("the game draws no helpers").
12. Mission tests pass no `--mode`, `--bots` or `--skill`: only Multiplayer maps get the Players-tab Testing settings.
