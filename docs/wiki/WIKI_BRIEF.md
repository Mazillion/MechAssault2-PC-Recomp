# How to add or correct a fact (contributor brief)

Short names: D = the folder that holds `merge_wiki.py` (`docs/wiki` in this repository), W = `D/wiki`.
Look things up first: `python wq.py "<regex>" [chars]` searches every fact (id, title, text, addresses, related
names) and prints one snippet per fact. Check a fact before you write a new one on the same subject.

## 1. What is hand-written and what is generated
- `W/facts/<pack>.json`: hand-written. The only source of facts. One file per topic pack.
- `W/pages/<pack>.md`: hand-written topic article, optional. The merge copies it in front of the pack's facts.
- `W/overrides.json`: hand-written corrections that the merge applies on top of the packs. Use it to change OLD facts.
- `W/wiki.json` and `W/WIKI.md`: generated by `merge_wiki.py`. Never edit them. WIKI.md is large: grep it, do not read it whole.
- `W/raw/functions.json`: the list of function start addresses, sizes, categories and owner names of the US retail
  `ma2.xbe`. It is only used to show the owning function in the address index.

## 2. Fact pack schema
File `W/facts/<pack>.json`, UTF-8 WITHOUT a BOM (a BOM or broken JSON makes the merge drop the whole pack):
`{"pack": "<file name without .json>", "title": "<topic title>", "facts": [ <fact>, ... ]}`

| Field | Required | Rule |
|---|---|---|
| `id` | yes | lower-case kebab-case, at most 60 characters, unique in the pack. Merged id = `<prefix>.<id>`, prefix = pack name up to the first `_` (`t28_release_polish_1110` -> `t28.`). |
| `title` | yes | one line; shown in the address index and the env-var list. |
| `subject` | yes | `{"kind": K, "id": text}`. K is one of: function, address, global, vtable, class, property, env_var, file, patch, asset, menu, setting, save, tool, concept. Kind function / address / vtable needs an address as id (it is added to `addresses`). Kind `env_var` lists the fact under that variable in "Environment variables". |
| `addresses` | yes (may be `[]`) | XBE virtual addresses as 8 upper-case hex digits (`"003AE754"`), range 00010000..005FFFFF. |
| `related` | yes (may be `[]`) | free names: merged fact ids (`t26.dsound-active-reinsert-freeze`), `sub_` names, classes, files, env vars. |
| `fact` | yes | 2-5 plain sentences: what it is, its effect, cause and fix. A fact with an empty `fact` is skipped without a message. |
| `how_to_use` | no | switch, env var, commit, where it shipped, how to test. |
| `status` | yes | `current`, `superseded`, `historical` or `open-question`. Nothing else. `current` is not printed in WIKI.md. |
| `confidence` | yes | `verified-in-game` (tested in a run), `code-confirmed` (read in code or disassembly), `documented` (stated in a note, not re-proven), `inferred`. |
| `source` | yes | a LIST of `{"file": "<where the evidence is>", "line": <number>}`. Cite the file by its path in this repository (for example `kit/source/game/src/scenario/ma2_scenario.c`); generated code is cited as `generated recomp_XXXX.c` (it is created at install time and is not in the repository). Evidence that is not a repository file (a run log, a measurement) may be left out of `source`; a pack from t28 on still needs one entry, so name the closest repository file. |
| `tags` | yes | list of short words. |
| `date` | yes | `"YYYY-MM-DD"`, the day of the finding or fix. |

Do not write a `pack` key inside a fact (the merge adds it). Never paste game data into a fact: no asset dumps, no
decoded text or dialogue, no file listings of the disc, no long hex blocks. Names, addresses, class and property names,
offsets and short ids are fine.

Address rule: an address is indexed when it is in 00010000..005FFFFF. Copy addresses exactly; this repository does not re-check them against the cited source files. An address that cannot be placed in the index is kept in `addresses_unverified`.

One real fact, copied from `W/facts/t04_scenario.json`:
```json
{
 "id": "scenario-scan-and-duplicates",
 "title": "Scan loads *.ma2map and skips duplicate ids",
 "subject": {"kind": "concept", "id": "scan / add_scenario"},
 "addresses": [],
 "related": ["scenario-folder-resolution", "test-file-focus", "scn-slot-limit"],
 "fact": "scan() loads every *.ma2map in the folder. A file that fails to parse is logged as [SCENARIO] and skipped. A second file with the same Id is skipped (the first one loaded wins). Only the first 200 scenarios are loaded.",
 "how_to_use": "",
 "status": "current",
 "confidence": "code-confirmed",
 "source": [{"file": "kit/source/game/src/scenario/ma2_scenario.c", "line": 1046}],
 "tags": ["scan", "duplicate"],
 "date": "2026-10-20"
}
```

## 3. Add a fact
1. Put new facts in a pack that fits the topic, or start a new pack `W/facts/t<NN>_<topic>.json` with a prefix nobody uses (see the
   existing file names; the prefixes t12, t13, t14, t15, t20 and t28 are each shared by two packs, so pick a new number).
2. Fill every field of section 2. In `how_to_use` name the commit and where it shipped.
3. Search for older facts your fact makes wrong (section 4): `python wq.py "<keyword>"`.

## 4. Supersede or correct an older fact
- Old fact: add an entry to `W/overrides.json`. Key = the MERGED id. Each field replaces the fact's field; the special key
  `append` adds a sentence to the end of `fact`. Example:
  `"t06.settings-frame-limit-presets": {"status": "superseded", "append": "SUPERSEDED 2026-11-04 (c3bee9c): ... See t28.frame-limit-no-unlimited-default-144."}`
  A key that matches no fact is ignored by the merge; `validate_wiki.py` reports it.
- A fact in a pack you own: edit it in the pack.
- Always: set `status` to `superseded` and name the merged id of the replacement in the text. If only one sentence is wrong, keep the
  status and append `CORRECTION <date>: ... (<new merged id>)`.

## 5. Rebuild (working directory = D)
```
python validate_wiki.py
python merge_wiki.py
```
`merge_wiki.py` takes a few seconds, rewrites `W/wiki.json` and `W/WIKI.md` and prints the statistics as JSON.

## 6. What proves a clean build
- `validate_wiki.py` ends with `0 errors, 0 warnings, <N> facts checked` and exit code 0.
- The merge statistics contain `"bad_fact_files": []`; `"facts"` = previous number + the facts you added (a smaller number means a
  fact was skipped).
- `grep -n "<your fact title>" wiki/WIKI.md | cut -c1-200` finds one line.

## 7. What the validator checks
Every pack: no BOM, valid JSON; no fact with an empty `fact`; no duplicate id in a pack; no merged-id collision.
`overrides.json`: every key is a merged id. Strict packs (t28 and later, packs named on the command line, or all with `--all`): `pack`
equals the file name; id kebab-case and at most 60 characters; one-line title; subject kind from the list; status and confidence from the
lists; date format; `addresses`, `related`, `tags` are lists; `source` is a non-empty list of `{file, line}`; each address is 8 upper-case
hex digits and in range. Warnings: unknown keys; a superseded fact that names no replacement id; a `related` entry shaped like `tNN.id`
that is no fact. `--all` also applies the strict checks to the older packs (many errors: their debt), so it is for information only.

## 8. Not in this repository
The wiki holds no game data. The object/property dictionary of the scenario editor, raw indexes of source files and environment variables, and the HTML search page are not part of this copy; the object-name links in `wiki.json` are therefore empty. Facts that came from a published strategy guide are left out.
